# 仅首次创建任务便笺：不抢焦点

已接入经本机验证的 stk 后台流程，版本 `background-create-v3`。新贴显示与任务链接返回由真实验收确认；前台应用、键盘焦点和剪贴板变更计数由 20 ms 采样检测。采样不是绝对无瞬态变化的保证。

## 日常自动创建入口

`/usr/bin/python3 /Users/cedric/.codex/hooks/stickies/create_note.py --receipt '<hook JSON>' --title '<项目｜任务>' --progress '<进展>' --next-step '<下一步>'`

- 已有便笺按任务链接只读去重，返回 exists，不重启、不修改、不重复创建。created/exists 回执持久去重。
- 新贴先保存待创建 RTF，再在桌面租约下执行 stk 离线写入。退出前备份，退出落盘后核对正文未变，写入仅新增一个 UUID 和索引项，然后 `open -g` 后台启动。
- 全程不用粘贴、按键、激活窗口、切 Space、搬动旧贴或恢复前台。只读 Peekaboo 使用 --no-remote，要求精确窗口快照和链接控件。
- Swift focus_guard 在执行前读取前台应用与焦点控件；Stickies 在前台或焦点不可读时拒绝执行。执行中采样前台应用、焦点控件和剪贴板 changeCount，不读取剪贴板内容。
- 检测失败返回 unavailable，保存报告并锁住该任务后续导入，不重试、不自动回滚用户数据、不切换前台。并发租约拒绝时不操作桌面。
- 全部程序检查通过才记录 created。真实链接点击验收沿用本机已通过的该路径，不在每次自动创建时强行点击链接。
- 已有便笺的正文、链接、位置、尺寸和样式均由用户维护，不自动更改。此任务在多轮间的布局变化经用户确认为手动调整。
- 报告和失败锁存放在 ~/.codex/hooks/stickies/validation/，运行备份在 ~/.stk/import-backups/，不提交这些用户数据。

## 用户明确授权的真实验证

本节是日常自动创建限制的例外，不是所有会话的默认创建权限。用户已给出的任务级授权跨轮有效，不重复询问。

- 用户明确授权真实验证、退出并后台重启时，可以使用 stk 离线创建本任务的一张新便笺；允许必要的应用退出、后台启动、只读 UI 观察及新便笺链接验证。不得使用前台粘贴或恢复焦点来冒充全程不抢焦点。
- 先保存既有便笺内容哈希、链接、窗口状态和可恢复备份。正常退出后再取持久化基线，区分应用自行保存的用户编辑与工具改动。不得丢失未保存的编辑。
- 创建只追加新便笺，既有便笺正文、链接、位置、样式均不改。应用必须在写入期间保持退出；若重新启动、数据变更或导入状态不明确，停止写入并检查，不能盲目重试。
- 后台重启期间记录前台应用与焦点，检查剪贴板未变。不得主动激活 Stickies、切 Space 或移动旧窗口。
- 验证新便笺真实显示、中文与换行正确、链接目标正确且可点击。点击若会改变当前焦点，不擅自执行，不将 RTF 字段或 AXLink 存在当作点击成功。
- 只有显示、链接点击、焦点保护及已有便笺保护全部通过，才接入自动 hook。未通过时保留实验接口，不自动部署。
- 本会话的用户已授权上述真实验证，且授权在规则生效后直接继续，无需再次确认。

规则版本：`background-create-v3`。改动 hook.py 只影响后续 UserPromptSubmit 注入，不追溯替换当前轮已经加载的限制。

## 当前验证边界

- Peekaboo 4.3.0 `set-value` 提供直接设置文本值和 `--no-auto-focus`，未提供富文本载荷参数。未验证其能创建便笺或保留可点击链接。
- 本机 Stickies 10.3 的 Info.plist 声明 Make Sticky 服务，支持 public.rtf；应用包没有发现 sdef 脚本字典。
- 二进制 x86_64 分支中，`makeStickyFromTextService:userData:error:` 转到 `makeStickiesFromPasteboard:`，后者调用 `openUntitledDocumentAndDisplay:error:`（display=true）和条件性的 `makeMainWindow`。这是静态证据，不能宣称后台运行验证失败或成功；目前不运行该服务，以免影响焦点。
- 未修改 Stickies 的内部持久化文件，未尝试绕过进程内缓存。直接写其内部目录不等于应用已经载入。
- 已验证 textutil 可生成保留中文、换行、任务 URL 的 RTF HYPERLINK。此结果不证明 Stickies 导入或 UI 链接点击成功。

后续后台导入必须独立证明：前台应用及焦点不变、剪贴板不变、仅产生一张新贴、中文和换行正确、UI 存在可点击链接、持久化链接目标正确。任何一项未证明，不自动回退前台粘贴。
